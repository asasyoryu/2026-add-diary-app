## 1. プロジェクト概要

### 1.1 目的

NCC 向け AI 駆動開発ハンズオン用の **日記アプリ** を、React Native（Expo）で拡張開発する。  
現状のテンプレート（ローカルメモリ上の簡易日記）を土台に、**クラウド永続化・認証・CRUD・検索・無限スクロール** を備えた実用的な v1 を完成させる。

### 1.2 背景

- テンプレートにはホーム（一覧）と新規作成のみが実装されている（`EntriesProvider` + シードデータ）。
- 必須要件として外部 BaaS への保存、5 系統の画面機能、拡張された日記フィールドが求められる。
- 開発環境は Expo SDK 54 / Expo Go を前提とする（`AGENTS.md` 参照）。

### 1.3 スコープ

**v1 に含める**

- Firebase（Authentication / Firestore / Storage）連携
- 認証（ログイン・新規登録・ログアウト）
- 日記の CRUD（作成・一覧・詳細・編集・削除）
- ホーム一覧の無限スクロール
- ホーム内検索（タイトル・本文）
- 日記フィールド: アイコン・タイトル・本文・日付・画像（任意）

**v1 に含めない（v2 以降）**

- パスワードリセット（メール送信）
- オフライン同期・競合解決
- 複数画像・動画添付
- タグ・カテゴリ・共有・コメント
- 全文検索（Algolia 等）やサーバー側検索 API
- Web 版の本番運用（Expo Web は開発確認程度）

## 4. 開発方針

### 4.1 全体

1. **既存 UI のトーンを維持** — 和紙風カラー（`#FAF6EE` 等）をベースに画面を追加する。
2. **段階的移行** — まず Firebase 接続と認証を通し、その後 CRUD・一覧・検索を実装する。
3. **データ層の分離** — `EntriesProvider` を Firestore 購読 + ページネーション対応のリポジトリに置き換え（またはラップ）し、画面はフック経由で利用する。
4. **シークレットをコミットしない** — Firebase 設定は `app.config` / 環境変数 / `.env`（gitignore）で管理。授業用のサンプルは `docs/` または `guides/` に手順のみ記載。
5. **Expo SDK 54 を厳守** — パッケージ追加・API 利用前に v54 公式ドキュメントを参照する。

### 4.2 コーディング

- 画面は `src/app/`（expo-router）に配置する。
- 共有ロジックは `src/store/` または `src/lib/` / `src/repositories/` に集約する。
- 新規コードは TypeScript strict に従い、`just check` が通る状態を維持する。
- 意味のある振る舞い（バリデーション、ページネーション、検索フィルタ）にはテストを追加する。

### 4.3 Git / 授業運用

- `origin` は自分の fork、`upstream` は教員リポジトリ（pull のみ）。
- コミット・push は fork に対して自由。本仕様の実装は feature ブランチ単位を推奨。

## 5. データモデル

### 5.1 Firestore コレクション

**パス**: `users/{userId}/entries/{entryId}`

| フィールド | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `icon` | string | ○ | プリセット絵文字 1 文字（例: `☀️`） |
| `title` | string | ○ | 1〜100 文字 |
| `body` | string | ○ | 1〜5000 文字 |
| `date` | timestamp | ○ | ユーザーが選んだ「日記の日」（時刻は 00:00 ローカルまたは UTC 統一で実装時に固定） |
| `imageUrl` | string | × | Storage のダウンロード URL |
| `imagePath` | string | × | Storage 上のパス（削除時に使用） |
| `createdAt` | timestamp | ○ | 作成日時（サーバーまたはクライアントで設定） |
| `updatedAt` | timestamp | ○ | 最終更新日時 |

**インデックス**

- 一覧・無限スクロール用: `date` DESC, `createdAt` DESC（複合インデックスを Firestore Console で作成）

### 5.2 Firebase Storage

**パス例**: `users/{userId}/entries/{entryId}/image.jpg`

- MIME: JPEG / PNG（実装時に `image-picker` の結果に合わせる）
- エントリ削除時に **オブジェクトも削除**する。

### 5.3 アイコン（プリセット）

現行 `MOODS` をベースに拡張する。v1 の初期セット（例・16 種）:

`☀️` `☁️` `🌧` `☕️` `🍜` `📚` `✨` `💭` `🌙` `🎵` `🏃` `🎉` `😴` `🧪` `🌸` `🔥`

- 必ず 1 つ選択済みで保存する（未選択のまま保存不可）。
- フィールド名は DB・型定義とも **`icon`** に統一（現行コードの `mood` からリネーム）。

### 5.4 バリデーション

| 項目 | ルール |
| --- | --- |
| アイコン | プリセット一覧に含まれること |
| タイトル | トリム後 1〜100 文字 |
| 本文 | トリム後 1〜5000 文字 |
| 日付 | 必須。日付ピッカーで選択 |
| 画像 | 任意。最大 1 枚 |

## 6. セキュリティ（Firebase Rules 方針）

### 6.1 Firestore

```
users/{userId}/entries/{entryId}
```

- `request.auth != null` かつ `request.auth.uid == userId` のときのみ read / write。
- 他ユーザーのドキュメントへの access は拒否。

### 6.2 Storage

- `users/{userId}/**` へのアップロード・読取・削除は `request.auth.uid == userId` のみ許可。

> ルールの具体文面は実装 PR で `firestore.rules` / `storage.rules`（または Firebase Console）に記載する。

## 7. 機能仕様

### 7.1 画面一覧

| 画面 | ルート（案） | 説明 |
| --- | --- | --- |
| ログイン | `/login` | メール・パスワードでサインイン |
| 新規登録 | `/signup` | アカウント作成後、自動または手動でログイン |
| 日記一覧（ホーム） | `/` または `/(app)/` | 一覧・検索・無限スクロール・FAB で新規作成 |
| 日記作成 | `/new` | 新規エントリ入力（モーダル推奨 — 現行踏襲） |
| 日記詳細 | `/entry/[id]` | 1 件の閲覧。編集・削除へ遷移 |
| 日記編集 | `/entry/[id]/edit` | 既存エントリの更新 |

**認証ガード**

- 未ログイン → ログイン画面へリダイレクト。
- ログイン済み → ログイン/新規登録画面はホームへリダイレクト。

**ログアウト**

- ホームまたは設定相当の UI から実行（ヘッダー右上のメニュー等。配置は実装時に決定）。

### 7.2 日記一覧（ホーム）

**表示**

- ヘッダー: 年月・「日記」タイトル（現行 UI を踏襲可）。
- **検索バー**: プレースホルダ例「タイトルや本文で検索」。
- リスト: 各カードに日付（日・曜日）、アイコン、タイトル、本文抜粋（2 行程度）、サムネイル（画像がある場合）。
- FAB: 新規作成へ遷移。

**無限スクロール**

- 初回: 最新 20 件を取得。
- リスト末尾付近で次の 20 件を `startAfter` で追加取得。
- ローディングインジケータ・「これ以上ありません」表示。
- 並び: `date` 降順 → 同値なら `createdAt` 降順。

**検索**

- 検索バー入力で **クライアント側フィルタ**（v1）。
- 対象: **タイトル・本文** のみ。部分一致、大文字小文字を区別しない。
- 検索文字列が空 → フィルタ解除（全件表示に戻る）。
- 検索中も並び順は上記と同じ。

**操作**

- カードタップ → 日記詳細へ。
- 「今日の記録」カード（任意維持）→ 新規作成へ。

### 7.3 日記作成

**入力項目**

| 項目 | UI | 必須 |
| --- | --- | --- |
| アイコン | プリセット絵文字グリッド | ○ |
| タイトル | `TextInput` | ○ |
| 本文 | 複数行 `TextInput` | ○ |
| 日付 | 日付ピッカー（デフォルト: 今日） | ○ |
| 画像 | 「写真を追加」→ ギャラリー or カメラ | × |

**保存**

- バリデーション通過後、Firestore に create。画像がある場合は先に Storage upload → URL / path をドキュメントに保存。
- 成功後、ホームへ戻る（または詳細へ遷移 — 実装時はホーム戻りをデフォルトとする）。

**キャンセル**

- 確認なしで戻る（未保存破棄）。

### 7.4 日記詳細

**表示**

- アイコン・タイトル・本文・日付（整形表示）・画像（あればフル幅表示）。

**操作**

- 「編集」→ 編集画面。
- 「削除」→ 確認ダイアログ → Firestore ドキュメント削除 + Storage 画像削除 → ホームへ。

### 7.5 日記編集

- 作成画面と同一フォーム。既存値をプリフィル。
- 日付・アイコン・タイトル・本文・画像（差し替え・削除）を変更可能。
- 画像削除時は Storage オブジェクトも削除し、`imageUrl` / `imagePath` をクリア。
- 保存で `updatedAt` を更新。

### 7.6 認証

| 機能 | 仕様 |
| --- | --- |
| ログイン | メール + パスワード。エラーはユーザー向けメッセージ表示 |
| 新規登録 | メール + パスワード（強度は Firebase デフォルトに従う） |
| ログアウト | `signOut` 後、ログイン画面へ |
| セッション | アプリ起動時に Auth 状態を復元。永続化は Firebase SDK デフォルト |

## 8. 非機能要件

| 項目 | 方針 |

## 9. 現行テンプレートからの変更点

## 10. 実装フェーズ（推奨順）

1. Firebase プロジェクト接続・環境変数・Auth/Firestore/Storage 初期設定
2. 認証画面（login / signup）と Auth ガード
3. Firestore リポジトリ + エントリ CRUD（画像なし）
4. ホーム一覧（FlatList + ページネーション）
5. 詳細・編集・削除
6. 画像アップロード（picker + Storage）
7. 検索バー + クライアントフィルタ
8. テスト追加・`just check` / `just test` 通過
